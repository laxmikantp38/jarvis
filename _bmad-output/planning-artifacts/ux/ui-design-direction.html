Design direction · 10 Aug 2026

A glass cockpit, not a hologram

You asked for a JARVIS HUD. The PRD says usability outranks the metaphor. This resolves that by reading “HUD” as instrumentation — an aircraft glass cockpit, mission-control telemetry — rather than glowing sci-fi decoration. Every panel is an instrument: a label bar, a severity stripe, and data set in tabular figures.

Palette

The ground is a blue-biased black, not neutral grey — it reads as a lit panel rather than an empty page. Accent cyan is desaturated so it never shouts. Semantic colours stay separate from the accent, so “behind trajectory” never competes with “this is interactive.”

Decisions behind the look

Severity is a stripe, not a colour swap

Every instrument carries a 2px stripe on its left edge. State reads at a glance from across the room, and it survives being printed, screenshotted, or viewed by someone colour-blind.

Accent ≠ semantic

Cyan means “you can act on this.” Amber and red mean “something is wrong.” They never share a hue, so an alert never looks like a button.

Data is monospaced, prose is not

Figures use tabular numerals so columns stay locked as values update. Sentences use a proportional face because the system talking to you should not look like a log file.

Committed to dark

An instrument panel is dark by nature, so this is single-theme by choice, with every colour painted explicitly rather than inherited. No light variant is faked.

Empty states are designed first

On day one you have no revenue history and no tasks. That screen was designed before the full one, because it is the screen you will actually see first.

System typefaces, deliberately

Web fonts are blocked in this environment and inlining a face would bloat the page. The stacks are chosen and treated — tracking, weight, scale — rather than left at defaults.
